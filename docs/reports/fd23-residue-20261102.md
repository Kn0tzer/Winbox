# FD-23 residue — select, pidfd_getfd, futex_waitv, and the per-number dispositions

Lane `lane-fd23res`, based on integration tip `cc1d89ab3`. This closes
what the FD-23 register entry left open after the 2026-10-31
disposition pass: `select` (23), `pidfd_getfd` (438) and
`futex_waitv` (449, both ABIs) are implemented against host-measured
contracts, and every remaining unimplemented number on both ABIs now
carries a recorded disposition. `rseq` (334) stays exactly as the
entry records it — a deliberate, loud `-ENOSYS` — and its real
prerequisite is filed as FD-102. Two further findings from this lane
are filed as FD-103 (the 64-bit `pselect6` never looks at its signal
mask) and, inside FD-103's closing terms, the unvalidated
`pselect6` timespec. Register closure: CL-52 (provisional number,
pending the merge audit). Fixing commit: `096d5b3e3` (the register
update and this record are the following commit on the same
branch).

## Host contracts (measured first)

Reference programs were run on the box's host kernel
(6.17.0-1020-oracle; sources and outputs in
`test-results/fd23res/hostref/`):

- **select**: writes back the *remaining* time (a 500 ms timeout with
  a descriptor ready at ~101–273 ms returned 0.399593/0.226909 s
  left; on expiry the timeval is zeroed). A bad descriptor in any
  set answers `EBADF` (select and pselect6 alike). Negative nfds
  answers `EINVAL`; `tv_usec = 1,000,000` is accepted (normalised);
  a negative sec or usec answers `EINVAL`. nfds above the
  descriptor-table size works on the host (2000 measured).
  `pselect6` does **not** write back its timespec. Bytes of the
  fd_sets past nfds are untouched.
- **pidfd_getfd**: `flags != 0` answers `EINVAL`, checked *before*
  the pidfd's validity. A non-pidfd descriptor, or a bad/negative
  target descriptor, answers `EBADF`. A terminated (zombie or
  reaped) target answers `ESRCH`. A target owned by another user
  answers `EPERM`. Success installs the descriptor with
  `FD_CLOEXEC` set, sharing the open file description (a read on
  the obtained descriptor advanced the shared offset).
- **futex_waitv**: a wake answers with the 0-based index of the
  woken entry. A value mismatch at entry answers `-EAGAIN`, and
  beats an already-expired timeout. An expired deadline answers
  `-ETIMEDOUT`. Only U32 entries exist (the size field must be
  `FUTEX_32`, value 0x02); valid entry flag bits are the size field,
  `FUTEX2_NUMA` (0x04, no effect) and `FUTEX_PRIVATE_FLAG` (0x80);
  `val` must fit 32 bits; a nonzero reserved field, a misaligned
  uaddr, nr outside [1,128], or per-call flags != 0 answer
  `EINVAL`. An unmapped waiters array or futex word answers
  `EFAULT`, and the whole array is validated before any address is
  pinned. Mixed private flags and duplicate addresses are allowed.
  clockid is `CLOCK_REALTIME` (0) or `CLOCK_MONOTONIC` (1) only,
  the timeout is absolute, and an invalid timespec answers
  `EINVAL`.

## What was implemented

- **select (x86-64)**: the `pselect6` body was factored into a
  shared core (`sys_select_core64`): the three fd_sets are
  translated to a pollfd array, waited on through the existing
  `kpoll`, and revents are translated back. The core adds the
  host's pre-checks both calls were missing — set pointers must be
  readable (`-EFAULT`) and every descriptor named in any set must
  be open (`-EBADF`) — which also corrects `pselect6`, whose old
  body silently ignored bad descriptors. select validates its
  timeval (`-EINVAL` for a negative field), normalises
  `usec >= 1e6` by folding it into the total, and writes the
  remaining time back after every completed wait, including an
  interrupted one; the fd_sets are only written on success.
  `pselect6` calls the same core and never writes its timespec
  back, as on the host.
- **pidfd_getfd (438, x86-64)**: a new dispatch case beside
  `pidfd_open`, in the host's exact check order (flags, pidfd,
  target liveness, owner, target descriptor), installing the
  obtained descriptor with `FD_CLOEXEC` over the source's object
  and access flags.
- **futex_waitv (449, both ABIs)**: `KThread::futexWaitv` (32-bit)
  and `KThread::futexWaitv64` (64-bit) park one ordinary futex slot
  per entry, all sharing one fresh condition, mask `0xFFFFFFFF`
  (the kernel queues waitv waiters MATCH_ANY); any slot's wake
  names the woken index. Registration — pending-wake consumption,
  slot allocation, condition assignment — happens entirely under
  the pending-wake mutex the existing WAKE paths already hold
  across their scan-and-record, so a wake can neither slip between
  the check and the registration nor observe a half-assigned slot;
  a wake that raced ahead of the wait is consumed from the pending
  table and answers with its index. Handlers on both ABIs validate
  the full array (host order above) before pinning any word, check
  each word is mapped (`-EFAULT`; the 64-bit RAM-pointer lookup
  alone answers for unmapped arena pages, so the mapping is
  checked explicitly), and convert the absolute timeout onto the
  futex machinery's millies clock (realtime by delta, as the
  existing futex timeout conversions do). The i386 table is
  extended from 440 to 462 slots so 449 dispatches at all, and its
  bounds check now uses the table's real size.
- **Per-number dispositions**: `tools/conformance/
  syscall_dispositions.json` records, for every number the census
  finds unimplemented on either ABI (404 entries), a disposition
  in seven categories — legacy-dead, superseded,
  privilege-surface, subsystem-absent, identity-model,
  ordinary-unimplemented, modern-unconsumed — each with its
  reason and the route by which the call would be served. The
  census tool gained an audit: run with the artifact present it
  reports `undispositioned_count` and `stale_dispositions_count`;
  both are 0 (see below). The generator used is kept with the
  evidence (`test-results/fd23res/gen_dispositions.py`).

## Stated boundaries (deliberate, recorded)

- select's nfds is capped at 1024 (`-EINVAL` above): the emulator's
  descriptor sets and the core's buffers are 1024 descriptors wide.
  The host accepts more; a guest asking for more here is refused
  loudly rather than served partially.
- A futex_waitv wider than the free futex-slot table answers
  `-ENOMEM` (the slot allocator panics on a full table; the host
  has no analogous failure, but refusing beats taking the emulator
  down).
- On the 32-bit side the woken index is proven for a wake consumed
  from the pending table and the wait machinery is the same code
  the 64-bit side proves with a blocked waiter; a 32-bit
  blocked-waiter wake needs a second running guest thread, which
  the native test harness's one running CPU cannot stage (the
  created worker thread never executes guest code). The 64-bit
  test proves the blocked-waiter wake at indexes 2 and 0.

## Filed from this lane

- **FD-102** — `rseq`'s recorded prerequisite stands between the
  loud refusal and any honest service: the 64-bit signal-delivery
  path must invoke a registered rseq critical section's abort
  handler on signal delivery (and on preemption and migration),
  or a guest running with a registered rseq area can be resumed
  inside an aborted critical section with its per-cpu data
  silently wrong. The refusal itself is unchanged by this lane.
- **FD-103** — the 64-bit `pselect6` ignores its sixth argument
  entirely: the signal mask is never read, validated, or applied,
  so a guest that blocks signals around the wait runs with the
  wrong mask for the whole wait; its timespec's nanosecond field
  is likewise never range-checked. Closing terms are in the
  entry.
