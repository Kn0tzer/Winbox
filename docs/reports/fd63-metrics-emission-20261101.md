# FD-63 — the METRICS stream stops mid-session: the emission gate did not count syscall dispatch as activity

Lane `lane-fd63` (worktree `/home/ubuntu/wt-fd63`), off integration
`1d932714c`. FD-63 is **convicted and fixed**; the register entry is
marked CLOSED with closure **CL-36** filed provisionally (CL-35 was
filed provisionally by the FD-54 lane on its branch; the composing
merge verifies by audit and renumbers if needed). Evidence:
`test-results/fd63/`.

## The filed evidence, read closely

FD-63 was filed from a 1,752 s demo run
(`test-results/fd55/long1/`): the console carries exactly three
`bw64: METRICS` lines (226.9 s, 227.4 s, 228.4 s) and none after,
while the session runs on for another ~1,500 s; the harness's
metrics.jsonl rows repeat the last snapshot's counters (syscall
calls=239, ms=46108.4) in every row.

The three emitted windows are the tell. All three are
SDL-present-driven: `present.path` is `"sdl"` with sdl=1/2/1, and
gl=0, audio=0 in every one — presents were the only activity in
those windows that the emission gate recognised. The frozen
snapshot's values (calls=239, ms=46108.39) are the third window's
syscall counters, verbatim.

## Mechanism

`bw64_metrics_maybe_emit` (`source/util/bw64metrics.cpp`) is the
registry's only emission path, called from every accounting hook.
Once the ~500 ms interval has elapsed, it emits the window only if
it sees activity: frame activity (Vulkan/SDL presents, Vulkan
frame completions) or bridge activity (GL stage calls, audio stage
calls). The **syscall stage was not counted** — although it is fed
by every 64-bit syscall dispatch (`source/kernel/syscall64.cpp`)
and is one of the three stages the emitted JSON reports.

A session whose remaining instrumented traffic is syscall dispatch
— a guest executing in its engine loop but presenting nothing,
which is exactly the filed run's shape after its window stopped
presenting through the SDL path — therefore reached the gate's
no-activity branch on every interval. That branch calls
`resetWindow()`, discarding the accumulated counters unreported,
and restarts the window clock. Every ~500 ms, for the rest of the
run: the panel froze at the last present-driven snapshot, and the
intervening measurements were destroyed, not merely unreported.

The emit lock is not involved: on the unfixed code, a window that
does hold a recognised activity emits immediately (the proof
below's drain step shows exactly that on the unfixed registry —
its first, residue-carrying window emits; the pure syscall-only
windows after it never do).

## Fix

`6d711e6a6`: the gate loads the syscall stage's call count and
counts it as bridge activity, with the reason written at the site.
Nothing else changes: the ~500 ms emit interval, the >2 s
stale-window drop, the first-window rule, the disabled gate
(`BW64_METRICS=0` / `bw64_metrics_set_enabled`) and the emitted
JSON schema are all untouched.

## Proof

The native metrics selftest (`tools/bw64metrics-selftest.cpp`,
which exercises the real registry, no Emscripten needed) gained a
section that drains the window, then drives **six successive
~600 ms intervals of syscall-only accounting** and requires at
least three emitted snapshots, the first carrying the window's
accumulated syscall calls (3).

- **RED** (final test file built against the integration tree's
  pristine `bw64metrics.cpp`): 24 PASS, exactly the two FD-63
  assertions FAIL (`test-results/fd63/selftest-red.log`). An
  earlier draft of the section, whose first window still carried
  a residue audio call from the preceding section, emitted once
  and then never again — the contamination was found, the section
  now drains first, and it restores the residue the fixture
  section was written against before it ends
  (`selftest-red-draft.log`).
- **GREEN** (fixed tree): SELFTEST PASSED, all sections
  (`selftest-green.log`).
- The writer's contract fixture, generated by the fixed tree, is
  byte-identical to the committed
  `web/tests/fixtures/frame-metrics-snapshot.txt` modulo the clock
  fields (winMs/frameMs/fps), so the committed fixture stands
  unchanged; the reader contract and panel unit tests pass 21/21
  (`js-contract.log`).
