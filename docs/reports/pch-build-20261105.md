# Precompiled shared header (PCH) for both project builds — lane record

Branch `lane-pch`, base integ `48d27952a`, code commit `73e0232cd`.
Worktree `/home/ubuntu/wt-pch`, prepared with the shared build store
(23 links, 0 payload bytes copied). Nothing pushed, nothing deployed.

## End state

Building the project no longer re-reads and re-processes the same large
shared header chain separately for every source file. 330 of the 336
project C++ sources include `boxedwine.h`, which pulls in the same chain
every time (STL, platform headers, the kernel/cpu core headers). Both
project makefiles now compile that chain once per build directory into
a precompiled header and let each of those translation units load the
serialized form instead:

- `project/emscripten/makefile` (clang/emcc): `boxedwine.h.pch` per
  BUILD_DIR, consumed with `-include-pch`.
- `project/linux/makefile` (GCC): `boxedwine.h.gch` per BUILD_DIR, in a
  `pch/` directory whose `boxedwine.h` is a symlink to the real header;
  consumers get `-I<pch dir>` first plus `-include boxedwine.h` and
  `-Winvalid-pch`, so a rejected precompiled header is loud, never a
  silent fallback.

The precompiled set is computed by membership in both makefiles:
project sources under `source/` and `platform/` only, minus the six
sources that do not include `boxedwine.h` (`jit64.cpp`, `jit64wasm.cpp`,
`bw64jitstats.cpp`, `bw64metrics.cpp`, `bwjittable.cpp`,
`ring_buffer.cpp`). Third-party sources under `lib/` are never in the
set. Each precompiled header is generated with a dependency file, so
every header in the chain is a prerequisite: editing one rebuilds the
precompiled header and, through it, every consumer. On the Linux side
the `.gch` also depends on the makefile's existing config stamp, so any
flag change rebuilds it. A sibling effort is adding a compiler result
cache to the same builds; this change neither uses nor depends on it
(all builds below ran with the plain `em++`/`g++` drivers).

## Measured improvement

Same tree, clean builds, `time` totals for the whole make run; the
box is shared, so total compiler CPU (user time) is the comparison
metric and wall time is reported with the load range observed.

| build | baseline real / user / sys | with PCH real / user / sys | user CPU |
| --- | --- | --- | --- |
| emscripten `wasm64-mt` (-j3) | 1024.6 / 853.6 / 79.9 s | 625.4 / 406.2 / 23.9 s | **-52%** |
| linux `test` (-j2) | 949.5 / 812.9 / 67.4 s | 384.5 / 405.5 / 38.4 s | **-50%** |
| linux `x64-test` (-j2) | 1071.6 / 943.1 / 67.1 s | 518.3 / 530.4 / 42.8 s | **-44%** |

The PCH wasm build ran concurrently with the native X64Test baseline
(heavier contention than its own baseline faced) and still halved CPU.
Per-file samples agree (user seconds, plain -> PCH): clang kthread.cpp
3.7-4.1 -> 1.6, fs.cpp 3.9-4.4 -> 1.7, bstring.cpp 3.3-3.7 -> 1.0-1.6;
GCC kthread.cpp 3.2-3.7 -> 2.0, fs.cpp 4.1-4.3 -> 2.5-2.8, bstring.cpp
3.0 -> 1.7. Coverage: 189 of 196 C++ units in wasm64-mt; 295 of 363
C++ units in the native test configurations (the rest are the 62
third-party units and the 6 named non-includers, by design). Logs:
`test-results/pch/baseline.log`, `pch-wasm.log`, `pch-native.log`.

## Defects found and filed

- **FD-173** — `source/emulation/cpu/common/cpu.h` defines the
  two-letter macros `u16`/`h16`/`u8`/`h8`; any unit that has seen the
  chain and then includes asmjit's headers fails (`Vec h8()` becomes
  an array declaration). Demonstrated by this lane's first native
  attempt (below). No in-tree unit fails today; filed as a latent
  build landmine with closing terms.
- **FD-174** — the Emscripten `test` target does not compile on the
  base: six units in `source/test/process/` need the multi-threaded
  configuration the target never defines. Census by `make test -k`:
  everything else builds (432 objects, every PCH consumer included);
  the six fail identically compiled plainly with the target's own
  flags, so the breakage is pre-existing and this change adds no new
  failure there. Evidence `test-results/pch/emtest-k.log`.

Also encountered, pre-existing and not this lane's: 
`scripts/build-jit-wasm.sh` aborts at its invalidation-gate build
with undefined references to `bwCurrentThreadRegistryLookup()` and
`FsOpenNode::noteMappedPagesReleased(...)` — the exact failure a
sibling lane already filed from the unmodified integ tip; the failing
compile lines are the script's own and pass through neither makefile
changed here (evidence `test-results/pch/selftest-and-emtest.log`).

## Two failures of this lane's first attempts, and their fixes

1. **Default-goal capture (emscripten makefile).** The first PCH rule
   was placed before the final-product rule, so it became make's
   default goal and the build "succeeded" after building only the
   .pch. Caught because the expected product was absent; fixed by
   moving the block after the product rule; re-verified by dry run
   (271 compile lines, 1 PCH build, the link line present).
2. **Silent pattern miss (both makefiles).** The first exclusion of
   third-party sources used a path pattern with two `%` wildcards;
   GNU make's filter silently did not match it, so two asmjit library
   units received the forced header and hit FD-173's collision.
   Replaced by the membership computation above and re-verified by
   dry-run censuses on both makefiles (without-PCH set is now exactly
   the 62 library units plus the 6 named sources in the test
   configurations).

## Costs and caveats

- The precompiled header costs one extra compile per build directory
  (clang .pch 26 MB; GCC .gch 126 MB on disk per configuration) and
  is rebuilt whenever a chain header or the flags change — measured
  builds above include that cost.
- The GCC mechanism forces `boxedwine.h` to the top of each consumer,
  matching how 330 of 336 sources already include it first; a future
  source whose include order is load-bearing against the chain will
  fail loudly at compile time (as FD-173's demonstration did), never
  silently.
- Configurations proven by building here: emscripten wasm64-mt,
  wasm64-selftest, and the `test` census; linux test and x64-test.
  The remaining targets of both makefiles (release, multiThreaded,
  wasm64-runelf, wasm64-mt-jit, the mem64 self-test, native release /
  x64 / x64-cache) use the same rules, the same membership set, and
  the same per-directory precompiled header by construction; they
  were not separately built in this lane.
