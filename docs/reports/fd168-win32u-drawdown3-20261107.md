## What shipped in this change

Four x86-64 win32u placeholders are now real implementations in the
Wine 8 backports build, via
`tools/buildWine/patches/wine8-win32u-fd168-slice3.patch`
(commit `40f40ee9e`), each an in-tree composition rather than a new
body of logic:

- NtUserDrawCaption — the spec line becomes a syscall entry whose
  body forwards to the tree's own full caption painter
  NtUserDrawCaptionTemp with the window's own font/icon/text
  (NULL/0 arguments), flags masked to the public caption bits
  0x103f: literally the call user32's own DrawCaption makes.
- NtGdiDrawEscape — spec stub to stdcall; the body is the
  no-output form of the existing NtGdiExtEscape wrapper.
- NtGdiPolyPatBlt — spec stub to stdcall, with the POLYPATBLT
  typedef added to wingdi.h; the body composes per-entry brush
  selection with NtGdiPatBlt under kernel semantics: the caller's
  rop is honoured, invalid-brush entries are skipped silently, an
  invalid DC returns FALSE, and count zero is a TRUE no-op.
- NtUserWindowFromPhysicalPoint — a new syscall-table entry
  forwarding to NtUserWindowFromPoint; this tree's
  physical/logical point mapping is already the identity.

The rebuilt win32u pair (win32u.dll `242c95ee…`, 359,038 B;
win32u.so `d1a2fa71…`, 1,492,984 B; FD-65 guard passes — freetype

## The caption return-value finding (FD-201)

Filed on the register from this lane's proof runs: in this
environment NtUserDrawCaptionTemp paints correctly but returns
0, and user32 DrawCaption with it, where the documented Windows
contract is nonzero on success. It is a property of the shipped
painter, present on the batch-10 runtime and the slice-3 runtime
alike, and not introduced by the new export (which agrees with
the painter exactly). A host-side reference could not be
obtained: the box's packaged Wine 9.0 did not finish its own
first-run prefix initialisation inside two bounded windows on
the loaded box, so whether host Wine returns nonzero for the
same calls is honestly unmeasured; the filing's closing terms
carry that measurement. Number FD-201 is lane-local to this
branch and renumbers when the batch composes.
