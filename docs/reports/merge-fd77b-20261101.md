## What the branch brings

FD-77 — the silent freeze (a fully booted session freezes solid before
its first window and never says why) — convicted and fixed on the
branch; the full account is the lane record
`docs/reports/fd77-msync-abba-20261101.md`, composed verbatim. In
short: the fault-stage instrument the register specified (per-thread
demand-path stage markers plus owner records on the per-process memory
mutex and the RAM allocator's mutex, kept as permanent dump tooling)
caught an msync / mapped-files ABBA deadlock on its first armed run —
`KProcess::msync` held the mapped-files mutex across a writeback that
demand-faults guest pages (memory mutex second), against the demand
path's memory -> mapped-files order. The fix snapshots the containing
mapping under the mutex and writes back after release; behaviour is
unchanged, and the pair's lock order is documented at the mutex
declaration. Proof on the branch: the deterministic test
`testMsyncLockOrder` (its sync point is the fault-stage marker, no
timing race) RED on unfixed code with the ABBA diagnosis, GREEN with
the fix; consumer series 6/6 mapped with zero parks on the fixed
build.
