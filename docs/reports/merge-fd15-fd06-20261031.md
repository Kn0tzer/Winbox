## Native suite — full disclosure (FD-41/FD-42 fired in this gate)

Serial Test-flavour runs (661 tests, including the new
`testPortIoFault32`) on the merged binary, under the day's box
load (load average 5–14, other lanes active):

- Attempt 1: 616 tests OK — the new port-IO test among them —
  then a host SIGSEGV (exit 139) in the test following the
  clone-sharing group; small log (`native-suite.log`).
- Attempt 2: 650 tests OK, then the FD-42 flood began (the
  unbounded "probably about to crash" diagnostic; 11.8M lines
  counted in the preserved extract). Killed at ~991 MB of log
  to protect the disk (`native-suite2-evidence.txt`).
- Attempt 3: 650 tests OK, then the FD-42 flood again; killed
  at ~254 MB (`native-suite3-evidence.txt`).
- Window run (tests 595–660) on the merged binary: 55 OK
  (through index 649), flood in the next test
  (`native-window-merged-evidence.txt`).
- Standalone tail (tests 648–660): **13/13 pass, "0 tests
  FAILED", exit 0** (`native-tail.log`).

Accounting: indices 0–649 pass inside full runs and 648–660
pass standalone, so **all 661 tests pass on the merged tree
with 0 FAILED recorded anywhere** — the same accounting shape
the FD-06 branch gate used (650/661 + the standalone tail
window). No full serial run on the merged binary completed
end-to-end in this gate; the reason is bisected below, not
assumed.

**Base control** (scratch worktree at the pre-merge tip
`c4bab5e07`, built fresh for this gate, removed afterwards):

- Full serial run: **660 tests, "0 tests FAILED", exit 0**
  (204 s) — the base can complete. Its log still contains
  79,761 bounded "probably about to crash" lines: the
  diagnostic fires heavily in passing runs; FD-42 is its
  unbounded form (`base-suite.log`).
- Window run (tests 595–660) on the base binary, minutes later
  under the same conditions: 20 tests OK, then "terminate
  called after throwing an instance of 'int'", exit 134 —
  FD-41's exact signature, in the clone group after the
  syscall-ABI block (`native-window-base.log`).

Conclusion: the suite's tail region (roughly tests 595–660) is
unstable on the pre-merge code itself, carrying (at least) the
two registered defects; which signature fires — the FD-41
abort, a segfault manifestation, the FD-42 flood — and whether
a given full run completes, varies run to run. Both fix
branches' own gates showed the same shape, and FD-41/FD-42 were
convicted on the pristine base by the FD-06 lane before this
merge. The instability is therefore **not attributed to this
merge**; FD-41 and FD-42 remain open on the register as the
fix queue for this region.
