# GL on WebGPU: 2026-10-20

## Status

The browser runtime includes a WebGL2-shaped `WebGPUGL` adapter for the GL64
bridge. The adapter handles buffer and vertex state, GLSL translation and
programs, uniforms, draw pipelines, texture state, framebuffer attachments,
CPU-mirrored blits, and synchronous readback. S0 through S2 are complete; S3
is partial because direct GPU presentation remains unfinished. The API survey is in
[gl-webgpu-api-list.md](gl-webgpu-api-list.md); tested pure-JS helpers are in
`web/gl-webgpu-utils.mjs`.

`glbackend=webgpu` selects the adapter, and the launcher defaults to WebGPU
after the triangle and framebuffer smoke checks. `glbackend=webgl2` selects the
legacy path. If WebGPU is unavailable or device creation fails, the bridge
restores its WebGL2 context. The browser export hashes the adapter files into
the runtime version so JS changes invalidate cached pages.

## Implemented support

- Buffers, vertex arrays, vertex attributes, index conversion, shader and
  program lifecycle, attribute and uniform lookup, and uniform setters.
- GLSL-to-WGSL translation through `web/shader.mjs` and `web/naga-rt.mjs`.
  Loose GLSL uniforms are reflected and rewritten into std140-compatible
  uniform blocks before translation; sampler uniforms use texture/sampler
  binding pairs.
- Cached render pipelines for array, indexed, and instanced draws, including
  blend, depth, cull, scissor, viewport, and color-mask state.
- 2D textures, subimage uploads, CPU box-filter mipmaps, texture parameter to
  sampler mapping, renderbuffers, texture-backed framebuffers, completeness
  checks, and CPU-mirrored color blits.
- Clear, fixed-function textured and vertex-color draws, and framebuffer
  clears/blits are mirrored in CPU memory so the bridge's synchronous
  `glReadPixels` and X11 presentation path can serve those cases.

The adapter's `_present()` copies its WebGPU color target to a worker-owned
offscreen canvas. The visible runtime still receives frames from the bridge's
synchronous readback path. A direct WebGPU frame transfer was tested, but it
failed the framebuffer gate because the GPU-presented offscreen blit region was
black; that change was reverted. Arbitrary WebGPU draw and texture output is
therefore not yet visible through the normal presentation path.

## Game probes (S4)

The probes used the default WebGPU backend and waited for a mapped window plus
60, 120, and 240 second captures. They did not reach a game menu or first
usable frame.

### Q3

The Q3 window mapped after 91.2 seconds. The first run stopped on a divide by
zero at `quake3e.x64.exe@0x8a248`; the reported `GL_MAX_TEXTURE_SIZE` had been
zero. Returning the device limit removed that exception. The retry stayed
black and logged `program 27 link failed: Not implemented: variable qualifier`.
Removing ES precision qualifiers did not resolve the translation error. Q3 is
partial and did not reach its menu.

### Mindustry

The first Java launch failed because its configured maximum heap was too small.
The temporary probe archive was adjusted to use `-Xms128m -Xmx512m`; the
repository game archive was not changed. The game also requires an OpenGL 3.2
profile for framebuffer support, so the probe now passes `glversion=3.2` by
default. With those settings its window mapped after 243.6 seconds and the FBO
check passed, then shader initialization failed with `UnexpectedNewLine` in
programs 5, 8, and 11. Expanding simple integer `#define`s in array lengths did
not resolve that translation error. Mindustry is partial and did not reach its
menu.

## Overnight status (Round 7, 2026-10-21)

### Q3

The bridge now snapshots guest-memory client arrays for each draw. For
`glDrawElements`, it reads the guest indices, computes the referenced vertex
range, copies only that range, and rebases indices; for `glDrawArrays`, it
stages the requested first/count range. Buffer-backed pointers advance by the
same base vertex. `glLockArraysEXT` and `glUnlockArraysEXT` resolve to no-ops.

The final WebGPU probe mapped a window after 48.2 seconds, but the composited
capture at 120 seconds is still black. The first three draw records
