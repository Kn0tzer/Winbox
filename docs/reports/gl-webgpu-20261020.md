# GL on WebGPU: 2026-10-20

## Current state

The browser runtime has an opt-in `WebGPUGL` context hook for the 64-bit GL
bridge. It retains Emscripten's real WebGL2 context and selects the adapter only
when `bwGlBackend=webgpu` or `glbackend=webgpu` is present. If WebGPU is
unavailable or device initialization fails, the bridge restores WebGL2. The
default remains WebGL2 until the framebuffer and triangle smoke checks pass.

The adapter creates a persistent WebGPU color and depth target, handles
`glClearColor`, `glClear`, viewport sizing and flush presentation, and mirrors
clear-color pixels so the bridge's synchronous `glReadPixels` path can present
them. It does not yet submit guest draw calls. The WebGPU canvas copy is
maintained alongside the existing X11 readback presentation path.

The S0 inventory is in [gl-webgpu-api-list.md](gl-webgpu-api-list.md). Pure-JS
utilities cover std140-style uniform packing, unsigned-byte index widening,
OpenGL blend-factor mapping and stable state-key hashing. These utilities have
four passing Node tests; shader translation and draw-pipeline integration are
not complete.

## Implemented files

- `web/gl-webgpu.mjs`: WebGPU context skeleton and WebGL-shaped state methods.
- `project/emscripten/gl-webgpu-bootstrap.js`: loads the adapter in the runtime
  realm before guest code starts.
- `source/opengl/gl64bridge.cpp`: opt-in `GLctx` replacement and WebGL2 recovery
  hook.
- `project/emscripten/wine64-launcher.js`: URL switch to `BW64_GL_BACKEND`.
- `project/emscripten/makefile`: includes the bootstrap in the JIT browser
  runtime.
- `web/gl-webgpu-utils.mjs` and
  `web/tests/suite/unit/gl-webgpu.test.mjs`: tested pure-JS helpers.

The browser export copies both adapter modules and includes their contents in
the runtime version hash so cached runtime pages reload them together.

## Limits and next work

The adapter's buffer, vertex-array, shader, program, uniform, texture,
framebuffer and draw methods are placeholders. Shader source is not yet routed
through `web/shader.mjs`; no WebGPU render pipeline is created for guest draws.
The CPU readback mirror only reflects clears, and framebuffer attachments,
`glBlitFramebuffer`, asynchronous GPU readback and fixed-function triangle
rendering remain unsupported. Q3 and Mindustry were not launched.

Next, implement buffer and vertex state, GLSL-to-WGSL compilation, uniforms and
draw submission; then add texture/FBO translation and run the framebuffer and
triangle checks before changing the default backend.
