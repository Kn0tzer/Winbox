open; this lane discharges two more of its named remainder

## What was implemented

### msvcp140_2 — all of it (44 x86-64 + 42 x86 slots)

The complete `__std_smf_*` set of ISO C++17 [sf.cmath], 22
functions in double and float forms: assoc_laguerre,
assoc_legendre, beta, comp_ellint_1/2/3, cyl_bessel_i/j/k,
cyl_neumann, ellint_1/2/3, expint, hermite, hypot3, laguerre,
legendre, riemann_zeta, sph_bessel, sph_legendre, sph_neumann.
Hand-written in `dlls/msvcp140_2/math.c` (carried by
`wine8-fd169r-crt2.patch` for the wine-8.0 x86-64 backports and
`wine10-fd169r-crt2.patch` for the wine-10.0 i386 rebuilds):

- Polynomials by their three-term recurrences.
- Elliptic integrals via Carlson's symmetric integrals
  R_F/R_C/R_D/R_J (duplication + asymptotic series); the
  third kind's principal-value region (ν > 1, pole crossings)
  via the DLMF 19.7.8 change-of-parameter relation, verified
  against quadrature references.
- Bessel functions by series, Hankel asymptotics and order
  recurrences (Miller backward for J, forward for Y and K);
  K by series near zero and by trapezoid quadrature of its
  integral representation for x > 2. The J/Y power series are
  summed in double-double arithmetic: near x = 16 their terms
  cancel by six orders of magnitude and plain double summation
  cannot resolve them to full accuracy (measured: 1.3e-7
  relative error in plain double, 5.5e-14 with the
  double-double terms). The double-double product uses the
  FMA form of the product error where the target provides
  one — on hosts where the compiler contracts `a*b - c` into
  an FMA (ARM64), the Dekker split form silently degrades to
  plain double; both paths were validated.
- Riemann zeta by Euler–Maclaurin with the reflection
  formula; beta in log space with argument shifting; expint
  by series and continued fraction.
- Conventions follow the standard, not the most common
  library habit: `assoc_legendre` carries NO Condon–Shortley
  phase (the phase belongs to `sph_legendre`'s definition) —
  `assoc_legendre(2,1,0.5) = +1.299038105676658`, matching
  ISO C++17 via cppreference and the libstdc++ correction
  (PR 83140).

Numerical validation (the dedicated pass the 2026-11-05 lane
deferred this family for): 2,703 cases against 50-digit
mpmath references. Worst relative error per family: hermite
1.7e-14, laguerre 8.7e-14, assoc_laguerre 1.6e-13 (extreme
orders), legendre 7.4e-16, assoc_legendre 3.5e-14,
sph_legendre 8.7e-12 (at l=m=60, θ≈0, value ≈1e-121), beta
5.7e-14, riemann_zeta 6.8e-15, expint 4.5e-15, ellint_1
6.3e-14, ellint_2 8.1e-15, ellint_3 see below,
comp_ellint_1/2/3 ≤ 1.1e-15, cyl_bessel_i 4.0e-14,
cyl_bessel_j 5.5e-14, cyl_bessel_k 2.8e-12 (at order 0.001,
where the defining combination divides by sin(μπ) ≈ 0.003),
cyl_neumann 2.8e-12, sph_bessel 9.8e-15, sph_neumann
1.2e-15, hypot3 exact. The only cases beyond 1e-9 relative
are three ellint_3 points at (k=0, ν∈{3,10}, φ≈π/2), where
the value is the difference of O(1) terms cancelling to
≈9e-5: worst relative 4.0e-10, absolute 3.5e-14 — the
double-precision floor for that cancellation, stated here
rather than tuned away.

### msvcp140_atomic_wait — 9 x86-64 + 5 x86 slots

Backported from upstream Wine (post-10.0 `main.c`), whose
bodies are the real implementations:

- `__std_execution_wait_on_uchar` /
  `__std_execution_wake_by_address_all` (WaitOnAddress /
  WakeByAddressAll).
- `__std_acquire_shared_mutex_for_instance` /
  `__std_release_shared_mutex_for_instance` (refcounted
  per-instance SRWLOCK table) — x86-64 only; the i386 build
  already carried them.
- `__std_calloc_crt` / `__std_free_crt` — x86-64 only, same
  reason.
- `__std_tzdb_delete_time_zones` /
  `__std_tzdb_delete_current_zone` /
  `__std_tzdb_delete_leap_seconds` — the real upstream
  memory-management code over the upstream tzdb struct
  layouts. Stated plainly: the matching getters stay stubs
  (below), so no getter-allocated struct can exist in the
  browser build yet; the deleters are nonetheless the genuine
  article, and the guest fixture exercises them on
  hand-built structs of the exact layouts.

## What stays stub, with its reason (unchanged from FD-169)

- The four tzdb **getters** (`get_time_zones`,
  `get_current_zone`, `get_leap_seconds`, `get_sys_info` +
  `delete_sys_info`): no time-zone database data source
  exists in the browser build. Upstream's own getter bodies
  answer with Windows zone names under a FIXME, and its
  leap-seconds getter returns an empty list — factually
  wrong (27 leap seconds exist). Fabricated data is not an
  implementation; they stay stubs. (14 atomic-wait slots per
  architecture remain, including
  compare_exchange_128 / the indirect-wait family, which are
  stub even in upstream master — STL-internal wait-table
  machinery with no authoritative public implementation.)
- concrt140 + the same names in msvcr100/110/120 (~400): a
  whole scheduler subsystem, not a function family.
- msvcp60/70/71 (~2,300): legacy STL ABIs.
- msvcp90-source remainders: deep C++ ABI work (codecvt,
  iostream and time facets).
- msvcm80/90 (528): mixed-mode C++/CLI assemblies — cannot
  exist as honest native DLLs in this environment.
- vcruntime140 exception-handling machinery, the msvcrtd
  debug heap, the __crt* UCRT/compiler plumbing, and the
  short unpinned-contract tail (_getsystime/_setsystime,
  the _d/_f/_ld libm helpers, the _mbcasemap data export).
