# Chromium 109 startup: 2026-10-16

Chromium 109.0.5414.120 (x86) now displays an offline page and runs its
JavaScript with software-only launch settings. The HADDPD crash and
font-initialization stack overflow are fixed. Mouse/keyboard verification,
configuration comparisons, performance tuning, and Portal work remain.

## First crash and repair

The earlier Unix exit logs reported zero because Wine's threads exited after
the Windows process was killed. The Wine server trace establishes that
Crashpad requested `terminate_process(handle=007c, exit_code=-36862)`.
Crashpad defines `0xffff7002` as a failed initial process snapshot:
[termination_codes.h](https://github.com/chromium/crashpad/blob/main/util/win/termination_codes.h).
The trace also records the failed cross-process memory read.

The preceding exception was on a Chromium worker, at chrome.dll RVA
`0xcebc25`: `66 0f 7c ff` (`HADDPD xmm7,xmm7`). CPU32's decoder entry
for this instruction was missing. The register-only instruction consequently
raised an access violation at address `0xffffffff`.

CPU32 now decodes register and memory HADDPD and sums each operand's two
double lanes. Both operands are copied before writing the destination, so
`HADDPD xmm7,xmm7` produces the same sum in both lanes.

## Validation

- New native regression failed before the fix (`LabelAlreadyBound` in the
  native JIT's invalid-instruction path), then passed with the fix. It covers
  all XMM register pairs, aliasing, memory sources, flags, and signed zero.
- The existing SSE3 guest fixture now includes Chromium's exact opcode and
  the memory form. It passes in the rebuilt browser runtime and QEMU i386:
  `MOVDDUP MOVSLDUP MOVSHDUP HADDPD PAGE_GUARD RESULT 0`.
- `pnpm test`: legacy checks and all 121 suite groups pass after removal of
  the previous thread's temporary exit diagnostics. The diagnostic patch is
  preserved in `/home/ubuntu/backups/boxedwine64-chromium-20261016/`.
- `pnpm typecheck` passes.
- Browser runtime WASM SHA256: `5d867f054c2dc4037afcc82d8d827f6b344cd4d2f92bce46bb4830e3d6372c31`.

## Font-initialization stack overflow

The first Chromium run after the repair passes the old worker crash point,
but overflows the main thread's stack at about 44.5 seconds. Wine reports
`EXCEPTION_STACK_OVERFLOW`, EIP `7bd24267`, in `RtlWakeAddressAll`.
The failure also occurs in normal multi-process mode. A stack dump reveals
the same six Chromium font-initialization frames repeating. The reduced
GDI/DirectWrite probe reports one font family (DejaVu Sans), no Tahoma, and
`DWRITE_E_NOFONT` (`88985002`) for `CreateFontFromLOGFONT(Tahoma)`.
Chromium's default-font fallback reenters initialization when that family
cannot be created.

Wine32's package omitted the architecture-independent Wine fonts that are
already present in the pinned Wine64 package. Adding those files to Wine32's
`/opt/wine-stable/share/wine/fonts/` changes the probe to six families, Tahoma
present, and successful DirectWrite font creation. The new `win32-fonts`
browser regression verifies GDI metrics and the DirectWrite family/mapping.

The export now stages those fonts in `glibc-rootfs32.zip`, leaving all pinned
source archives unchanged. Font hashes and the derived archive hash are
recorded in `wine32-font-provenance.json` and included in the runtime evidence
fingerprint. Unit checks preserve original archive members and verify
idempotency and failure before mutation if required fonts are missing.

## Software rendering

With the fonts restored, normal multi-process Chromium maps a window after
about 29.7 seconds and remains alive for the 150-second observation. Its
window is mostly black with a small colored line, so this does not establish
readable rendering or interaction. The earlier minimal Win32 window renders
white pixels and readable text. Software-only compositor/occlusion settings
produced readable Chromium UI and the offline smoke page in
`test-results/chromium-software-smoke/`. The page set its title to
`BW_RENDER_OK` and displayed a completed one-million-iteration JavaScript loop
(`2468 ms` in that run). This configuration adds `--single-process`,
`--in-process-gpu`, `--disable-software-rasterizer`, `--use-gl=disabled`,
`--disable-features=CalculateNativeWinOcclusion,DirectComposition`, and
`--disable-backgrounding-occluded-windows` to the earlier GPU-disabled flags.
The individual required switches have not yet been isolated.

The permanent font export passes its Wine32 browser regression, all 122 fast
suite groups plus legacy tests, and the archive/fingerprint provenance tests.

Raw evidence remains in `test-results/chromium-resume-server/`,
`test-results/chromium-resume-seh/`, `test-results/suite-cpu32-sse3/`, and
`test-results/chromium-haddpd-first/`. A passing instruction fixture does
not establish successful Chromium rendering or browsing.
