# Tooling honesty — cleanup-wave record (2026-10-30)

Lane: test harnesses, build scripts, and developer tooling.
Worktree `wt-tooling`, branch `lane-tooling-honesty`, based on the
integration tip `538f03db5`. Standard followed:
`docs/failure-logging-and-recovery.md` (pathfinder lane) and the
clean-up skill. Nothing pushed; the live site was never touched.

End state pursued: every harness either runs and reports honestly,
or fails loudly and immediately naming why; no script reports
success for work that did not happen.

## Fixed

1. **Probe server started happily against a missing dist.**
   Severity: required. `tools/browser/serve.mjs`'s `serve()` never
   checked that its root exists; against a fresh worktree (no `dist/`
   yet) it started a server that 404s every asset, and probes burned
   their whole boot budget before failing with a misleading timeout.
   `serve()` now stats the root first and throws a `BW64-FAIL` line
   naming the path and the remedy. Regression tests:
   `web/tests/serve-preflight.test.mjs` (3 tests). Sabotage-checked
   against the pre-fix server, which started silently on the same
   input. Commit `96ffa5d29`.

2. **D3D12 system oracles died invisibly on unstaged trees — the
   state that got them declared "broken box-wide".** Severity:
   required. `web/tests/d3d12-system.mjs` and `d3d12-32-system.mjs`
   served and booted with no preflight; on any tree whose wine zips
   were not staged, guests died `c0000135` (DLL not found) deep in
   the spawn path and the run read as an emulator failure. Both now
   run a loud preflight before serving (dist runtime files present;
   the probe exe staged in `prefix64.zip`; the D3D12/Vulkan DLLs
   present in the wine zips — checked with python3 zipfile, the
   repo's existing pattern) and fail in seconds naming the missing
   piece and the staging command; a `c0000135` verdict line at the
   end names the likely cause. Also fixed here: the oracles imported
   probe-slots through an absolute path into the main tree; they now
   use the relative `./probe-slots.mjs` like every suite test.
   Verified negatives: missing dist → rc 1 in seconds naming the
   file; real-but-unstaged zips → names the unstaged member and the
   fix. Commit `708f9e0c2`. Positive direction, run after this
   lane's own dist was built and staged: `PREFLIGHT OK`, then a real
   guest run — `D3D12 VERDICT {"passed":true,"tri12Result":0}`,
   rc 0. The oracle declared broken box-wide this morning works;
   it was the missing staging precondition that was invisible.

3. **A build could verify a stale dist and report success for the
   new one; a queued build sat silent.** Severity: required.
   `tools/bw64-build.sh`'s verify step resolved its target as
   `BW_TEST_DIST || WINE_BUILD_OUT || dist` while the exporter
   writes `WINE_BUILD_OUT || dist`; with the suites' `BW_TEST_DIST`
   set, a build verified an old dist and claimed completion for the
   unverified new one. The verifier is now pinned to the export
   output this run just produced. Separately, both lock-wait loops
   now log once that they are waiting, naming the lock owner (the
   probe-drain loop already modelled this); a queued build
   previously sat silent for up to ten minutes with a 0-byte log —
   observed live with this lane's own first queued build, and the
   fixed message was observed from the relaunched one. Commit
   `366b1a227`.

4. **The D3D conformance runner always exited 0.** Severity:
   required. `web/tests/d3d-conformance.mjs` caught every failure
   into `results.json` — suite errors, guests that never printed
   DONE, op-level FAILs — and exited 0 with no verdict line, while
   `CATALOG.md` names it as the D3D9–D3D12 runner: any exit-code
   caller recorded success for fully failed runs. It now computes a
   verdict (suite error / DONE never printed / zero ops recorded /
   any op FAIL / runner error) and exits non-zero on failure; a
   clean run prints `D3D CONFORMANCE PASS` with per-suite op
   counts. Verified live: an empty suite filter now prints a
   `BW64-FAIL` line and exits 1 (previously exit 0). Commit
   `56d091d83`.

5. **Stale catalog instructions for the D3D12 oracles.**
   `web/tests/CATALOG.md` claimed there was "no dedicated D3D12
   32-bit runner" and omitted both system oracles. The row now names
   both runners and records their staging precondition. Commit
   `3f731ab1e`.

6. **Vulkan marshal generator panicked on a guest-controlled type
   field** (referred by the graphics-bridges lane). Severity:
   required. The autogenerated
   `MarshalVkPerformanceValueINTEL::read/write` `kpanic`-ed on the
   `type` field read from guest memory (unknown type in both
   directions, plus the STRING case on write) — a guest-supplied
   value killing the whole emulator. Fixed in the generator
   (`tools/vulkan/gen/src/boxedwine/org/marshal/
   VkHostMarshalType.java`), not the generated file: all three
   sites now emit the subsystem's established log-once shape
   (`klog_fmt` + static shown flag, cf. `vk_host.cpp`'s pNext
   handlers) with a `BW64-FAIL` line naming the bad value, and skip
   the payload. The union slot is fixed-stride (`address += 8` both
   directions, unchanged); read also zeroes the value so no
   uninitialised data flows to the host call. The regenerated
   `vk_host_marshal.cpp` is committed with the generator change; its
   diff is exactly these two functions. Baseline evidence:
   regenerating with the *unmodified* generator reproduces the
   checked-in marshal file byte-identically. Verified: regenerated
   TU compiles (`g++ -fsyntax-only`, project flags); zero
   PerformanceValueINTEL panics remain; silent-failure scanner tests
   13/13 pass. No guest-level test exercises the INTEL performance
   path, so behaviour proof is the scoped diff + compile +
   inspection — stated plainly. Commit `3c2f790bb`.
   Environment note: the box had a JRE only; `default-jdk-headless`
   was installed to compile the generator.
   Same-pattern follow-ups NOT in the referral's scope, recorded so
   they are not lost: `VkIndirectExecutionSetCreateInfoEXT` and
   `VkDescriptorGetInfoEXT` discriminator panics in the same
   generator (their unions carry handles/pointers, so the degrade
   needs its own stride/ownership check), and the
   `vulkanGetNextPtr`/`vulkanWriteNextPtr` `kpanic_fmt` emissions
   in `writers/VkHost.java`.
   **Hazard found while baselining:** regeneration is NOT wholesale
   safe. The checked-in `source/vulkan/vk_host.cpp` carries
   hand-written implementations the generator does not emit
   (initVulkan error propagation, mapVkMemory failure handling,
   push-descriptor-template support, log-once unsupported ops); a
   full regen silently reverts them (baseline regen diff: 66+/69−
   in that one file). The drift was restored after each generator
   run in this lane and is flagged here for the coordinator: either
   the generator must learn those implementations, or `vk_host.cpp`
   must stop pretending to be generated.

7. **`bw64-build.sh` printed BUILD COMPLETE for a failed export —
   the campaign's named trap, mechanism convicted live.** Severity:
   required. This lane's own first full build hit it end-to-end:
   `stage-dependencies.py` died on a missing DXVK payload
   (`tools/dxvk/build.w32/src/d3d9/d3d9.dll`, absent in a fresh
   tree), `build.mjs` exited 1 with an uncaught-error trace — and
   the script printed `BUILD COMPLETE` and exited 0. Root cause:
   the final export line was a bare
   `node build.mjs && BW_TEST_DIST=… node verify-dist.mjs`
   statement; an `&&` list consumes the failure status, so `set -e`
   never fires, verification is silently skipped, and the success
   banner was unconditional. Both steps now `die` loudly by name
   through the script's own idiom. Commit `f92549354`. Proof: the
   pre-fix failure is preserved in this lane's build log (export
   trace immediately followed by the banner); post-fix, the same
   wrapper ran the positive path end-to-end once payloads were
   staged — export verified (dependency archive hash matched the
   staged payload) and only then BUILD COMPLETE, rc 0. A post-fix
   *negative* rerun through the full wrapper was pre-empted three
   times by the probe gate (the script refuses to run while a probe
   holds a slot — itself a loud, immediate, named failure at rc 1),
   so the negative direction rests on the preserved pre-fix log
   plus the `die()` semantics used uniformly across the script;
   stated plainly rather than claimed as re-run.
