### Out-of-lane gaps observed from `tools/` (NEEDS_OTHER_LANE)

- **Kernel (`source/kernel/syscall64.cpp`)**: `X64_SYS_clone` without a thread/memory64 context returns `-K_ENOSYS` (`:4641-4651`). The `fork`/`vfork` syscalls (57/58) have no dispatch case and fall through to the default unimplemented path (`:4893-4917`), which logs rate-limited and returns ENOSYS. glibc `_Fork` issues `clone(SIGCHLD|…)` on x86-64; this is not verified against the glibc in this build. Process creation from guest code is therefore unimplemented. Required change: implement fork/vfork/clone-without-CLONE_VM as real process creation, with tests.
- **CPU (`source/emulation/cpu/cpu64.cpp:2852`)**: AVX/AVX2 are hidden from CPUID. The required change is an owner decision: implement AVX or accept the incompatibility with a loud, evidenced rejection.
- **Vulkan (`source/vulkan/vk64bridge.cpp:3641-3648`)**: the `vk64: asked-for (unimplemented)` log is not rate-limited. Required change: rate-limit it per name, and confirm the extensions denylisted by `tools/vkd3d/probe/gen_vk64pe.py:115-122` are absent from `vkEnumerateDeviceExtensionProperties`.
- **Vulkan coverage (`tools/vkcov/METHOD.md:14-16`)**: 99 vk64 exports are stub-only, and vk32 is trap-only (303 exports). Recorded as known unimplemented surface; implementation belongs to the vk lane.
- **Vulkan work list (`tools/vkd3d/ICD_WORK_ITEMS.md:28,222,225`)**: push descriptors "not supported", flush as logged no-op, query pools listed as work items. Owned by the vk lane.
- **Wine patch (`tools/buildWine/patches/wine5-lz.patch:235,297`)**: `FIXME("flags 0x%x ignored")` for `GetFileVersionInfoEx`. Logged through Wine's channel. Low severity; behaviour is inherited from upstream Wine.
