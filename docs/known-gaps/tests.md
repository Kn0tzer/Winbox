## Explicit external ownership blocker

`web/tests/suite/unit/vk32-dispatch.test.mjs:39-52` still has a pointer-width assertion containing `|| true` and catches missing shim reads. It matches the excluded `vk*.test.mjs` pattern, so this lane did not edit it. Required owning-lane change: read `tools/rootfs64/libvk32/libvk32.c` and assert `P(x)` zero-extends guest pointers to 64-bit trap slots, including the `VkSubmitInfo` pointer. This leaves that test weak until its owning lane makes the change.

## Verification limits

- The required unit and launcher UI runs are recorded in the final work report.
- This worktree has no `dist/runtime/`; ZIP-byte and exported metadata assertions therefore skip explicitly. No WASM build was run.
- There are no `.todo()` or unconditional browser-test skips. Conditional skips are the optional Celeste archive, optional cross-compilers, and absent export artifacts above.
- Suite cleanup catches are best-effort teardown only. Several standalone diagnostics also catch browser/server cleanup, missing optional build provenance, or guest-file reads; those are diagnostics, not passing unit assertions.
- `web/tests/suite/unit/vk32-dispatch.test.mjs` is the only remaining unconditional `|| true` found in suite unit tests; it is listed above as an ownership blocker.
