# Vulkan known-gap audit

Initial source audit register for lane P2-V. It includes requested grep hits, source-level `default:` arms, empty `catch` arms, replay skip/drop counters, and identified SPIR-V/WGSL rejection sites. Original audit rows are followed by disposition updates as fixes land; unresolved rows remain OPEN. Some grep matches are scanner duplicates within one behavior and still need consolidation into behavior-level rows.

Rows: 365 source and follow-up rows (67 IMPLEMENTED, 66 REJECTED-LOUDLY, 232 NOT-A-GAP, 0 OPEN). ## Sampler disposition appendix (2026-10-25, owning lane)

The 3 rows reopened by the citation re-pin are dispositioned here. Evidence
was gathered before deciding: the bridge's feature/limit advertisements

**Mip LOD bias (row citing `vk64bridge.cpp:478`) — NOT-A-GAP.** WebGPU
samplers have no LOD bias, so the honest advertisement is the limit the
tier can honour: `fillLimits` now reports `maxSamplerLodBias = 0.0f`
(it previously reported 2.0f while honouring none of it — the false
advertisement was the gap). Under VUID-VkSamplerCreateInfo-mipLodBias-01069
no conforming guest can request a nonzero bias from a device advertising
0, and the spec clamps the effective bias to +/-maxSamplerLodBias
regardless, so applying no bias is the advertised behaviour. Out-of-contract
requests stay loudly logged (`sampler-mip-lod-bias`) and creation succeeds.
Rejection was not chosen: the value is core sampler state that a guest
stack may set speculatively, and failing creation for it buys nothing once
the advertisement is truthful. Pinned by `vk-sampler-rejection.test.mjs`
(limit value, log token, no rejection).

**Clamp-to-border (row citing `vk64bridge.cpp:475`) — APPROXIMATION,
documented deviation (not a closure state).** Unlike mirror-clamp (feature
bit, advertised FALSE, rejected) and LOD bias (limit, now advertised 0),

no advertisement lever, and a conforming guest may always create such a
sampler. WebGPU has no border addressing or border colour (decoder:
`web/vk-protocol.mjs:89-90`; descriptor: `web/vkwebgpu.mjs:214-215`), and a

rejected itself: failing core sampler creation makes DXVK throw from
vkCreateSampler wherever D3D9/D3D11 border addressing is used
(shadow-map PCF, edge fade), converting a latent visual approximation into
a hard failure of conforming guests. The approximation therefore stays,
described in the row exactly as the code behaves, logged per sampler as
`sampler-border-colour` with the colour value, and pinned by
`vk-sampler-rejection.test.mjs`. The demo-log sweep found no workload
creating a border sampler today, so the deviation is latent. It remains
tracked here as a deviation, explicitly NOT counted as IMPLEMENTED,
REJECTED-LOUDLY, or NOT-A-GAP; closing it requires either the
shader-emulation feature (IMPLEMENTED) or a project decision to fail a
core feature loudly (REJECTED-LOUDLY).

## Addendum — DirectX 12 campaign dispositions (2026-10-26, lane-vkd3d)

Full evidence: `docs/reports/d3d12-campaign-state-20261026.md`. The changes
below were forced by vkd3d-proton 3.1.0's device bring-up and first
programs; each was probe-verified in the browser (tags d3d12-patch1..7,
d3d12-draw1..6, d3d12-scene1..3). Summary of re-dispositions:

- **Compute shader modules / compute pipelines** (row for
  `spirv-compute-entry`, and the CMD_DISPATCH row): module creation no
  longer rejects compute-only modules, and `vkCreateComputePipelines`
  creates real pipeline objects in both ABIs. Execution is unchanged:
  `vkCmdDispatch` still records CMD_DISPATCH and the submit emitter drops
  it loudly (`compute-dispatch`). Rationale: vkd3d eagerly builds compute
  pipelines (clear-UAV, execute-indirect, dstorage) during device creation
  and treats refusal as device-fatal; creation success with loud
  execution-drop keeps D3D12 devices usable for graphics while compute
  results remain honestly absent. Tests: `vk-spirv-rejections.test.mjs`,
  `tools/vkd3d/tests/vk64_native_test.cpp` (both ABIs' compute blocks).
- **Timeline semaphore submits** (row at `vk64bridge.cpp:6236,9424`): the
  register previously claimed submit ordering IMPLEMENTED, but the submit
  paths in fact rejected any batch carrying a timeline signal
  (`VK_ERROR_FEATURE_NOT_PRESENT`), discarding all of vkd3d's queue work
  while D3D12 calls kept reporting success. The submit paths (v1/v2, both
  ABIs) now apply timeline signals to the semaphore counter (monotonic,
  signal paths only) and let batches proceed; waits on unreached values
  log `timeline-semaphore-wait` and proceed — they never fabricate a
  signal (the pre-existing anti-fabrication pin still holds). Tests:
  `vk-timeline-semaphore.test.mjs`, `vk-binary-semaphore.test.mjs`.
- **Geometry stage**: SPIR-V capability 2 and pipelines carrying a
  geometry stage are now RECORDED (`Pipeline.gs`) instead of rejected at
  creation; draws under such a pipeline are dropped loudly at submit
  (`geometry-stage-draw`). Tessellation/task/mesh stages still reject at
  creation. Tests: `vk-pipeline-rejection.test.mjs`, native geometry
  block.
- **Descriptor-set counts** (rows citing `maxBoundDescriptorSets = 3`):
  the advertised limit is now `VK64_MAX_SETS` (8) and both
  `vkCreatePipelineLayout` handlers record layouts up to 8 sets (vkd3d
  root signatures require 6). The old NOT-A-GAP reasoning ("layouts above
  3 sets cannot exist") no longer holds by construction: what a shader
  may use is remapped by the page tier at pipeline build — non-push
  groups are compacted into the device's bind-group budget (push stays
  at group 3) and draw-time set lookups still resolve the guest's
  original set index; only a pipeline needing more groups than the
  device offers fails loudly (`group-count-limit` in `web/vkwebgpu.mjs`).
  Test: `vk-capabilities.test.mjs`, `vk-descriptor-group-remap.test.mjs`.
