# Vulkan known-gap audit

Initial source audit register for lane P2-V. It includes requested grep hits, source-level `default:` arms, empty `catch` arms, replay skip/drop counters, and identified SPIR-V/WGSL rejection sites. Original audit rows are followed by disposition updates as fixes land; unresolved rows remain OPEN. Some grep matches are scanner duplicates within one behavior and still need consolidation into behavior-level rows.

Rows: 350 source and follow-up rows (45 IMPLEMENTED, 71 REJECTED-LOUDLY, 233 NOT-A-GAP, 1 OPEN). The five OPEN real-workload findings were added by sol-b; historical closure claims below describe the earlier source audit. Recount and closure verified 2026-10-25: the 3 pipeline-result OPEN rows were closed as REJECTED-LOUDLY (page-tier fail-closed; see those rows and the spot-check appendix at the end of this file). Citation re-pin 2026-10-25 (audit wave-2 fix lane): every line citation was re-verified against the tree and 3 rows were reopened (two sampler rows whose text claimed a rejection the code does not perform; one marker row whose quoted comment no longer exists); see the re-pin appendix at the end of this file. Sampler disposition 2026-10-25 (owning lane): the 3 reopened rows are dispositioned — mip LOD bias is NOT-A-GAP via the advertised maxSamplerLodBias limit of 0, clamp-to-border is a documented APPROXIMATION (not one of the three closure states; evidence in the sampler disposition appendix), and the dead marker row was deleted (its referent behaviour is covered by the compute-pipeline rows); see the sampler disposition appendix at the end of this file. Border-colour closure 2026-10-25 (border emulation lane): the clamp-to-border APPROXIMATION is superseded by shader-tier border emulation and the row is IMPLEMENTED; no APPROXIMATION rows remain (see the border closure addendum in the sampler disposition appendix). Portal/device-creation closure 2026-10-25 (portalfix lane): four of the five sol-b OPEN rows are IMPLEMENTED (Portal device creation, actual swapchain selection, synchronous readback prefix loss, multi-command-buffer timing overcount); the serialization-cost row remains OPEN, and the device-creation fix exposed one new OPEN row (unsubmitted-command-buffer fallback). Fallback closure 2026-10-25 (vkfallback lane): that row is IMPLEMENTED — the scan's type guard was a do{}while(0) macro whose loop swallowed its continue, so the scan read command-buffer fields in every live object; it now uses an explicit kind guard plus a recording-lifecycle gate (ended, not-yet-submitted only). The one remaining OPEN row is the serialization-cost row. The texel-buffer-view row moved from REJECTED-LOUDLY to IMPLEMENTED for uniform views; storage texel views remain rejected. Macro-class closure 2026-10-25 (vkmacro lane): the fallback row's root cause was one instance of a macro class -- VK64_DROP_IF wrapped its action in do{}while(0), so all 58 continue/break guard sites in the bridge logged their drop and fell through; the macro is now an if/else{} statement (flow control binds to the caller's loop/switch, and unbraced-if-arm misuse is a compile error), closing the class with 55 LIVE sites fixed and 3 BENIGN sites subsumption-cited; see the new row in the real-workload table below and docs/reports/vk64-drop-if-macro-audit-20261025.md. The one remaining OPEN row is still the serialization-cost row. Capability-audit closure 2026-10-25 (spirvcaps lane): the SPIR-V audit's unknown-capability catch-all rejected capabilities the page tier verifiably translates -- including 50 ImageQuery, declared by every DXVK module -- so effectively all DXVK shader creation failed; the translated set {32, 43, 50, 51, 5379} is now whitelisted with per-cap pins, and 33 CullDistance / 4427 DrawParameters (likewise declared unconditionally by DXVK) are exempted only in their declared-but-unused form and stay rejected loudly when used; see the new row in the real-workload table below. The same lane's workload probe also supplied the multi-command-buffer confirmation the timing-overcount row was waiting on. The one remaining OPEN row is still the serialization-cost row.

## Sampler disposition appendix (2026-10-25, owning lane)

The 3 rows reopened by the citation re-pin are dispositioned here. Evidence
was gathered before deciding: the bridge's feature/limit advertisements
(`fillCoreFeatures` memsets to 0 and never sets `samplerMirrorClampToEdge`;
`fillVulkan12Features` likewise leaves it FALSE; `fillLimits` is shared by
both ABIs), the page tier's sampler capability (`web/vk-protocol.mjs`,
`web/vkwebgpu.mjs`), the Vulkan valid-usage rules, and a sweep of every
retained demo-matrix console log on the box for the audit tokens
(`sampler-border-colour`, `sampler-mip-lod-bias`, `mirror-clamp-to-edge`,
any `vk64: UNSUPPORTED` line): zero occurrences in any demo run.

**Mip LOD bias (row citing `vk64bridge.cpp:478`) — NOT-A-GAP.** WebGPU
samplers have no LOD bias, so the honest advertisement is the limit the
tier can honour: `fillLimits` now reports `maxSamplerLodBias = 0.0f`
(it previously reported 2.0f while honouring none of it — the false
advertisement was the gap). Under VUID-VkSamplerCreateInfo-mipLodBias-01069
no conforming guest can request a nonzero bias from a device advertising
0, and the spec clamps the effective bias to +/-maxSamplerLodBias
regardless, so applying no bias is the advertised behaviour. Out-of-contract
requests stay loudly logged (`sampler-mip-lod-bias`) and creation succeeds.
Rejection was not chosen: the value is core sampler state that a guest
stack may set speculatively, and failing creation for it buys nothing once
the advertisement is truthful. Pinned by `vk-sampler-rejection.test.mjs`
(limit value, log token, no rejection).

**Clamp-to-border (row citing `vk64bridge.cpp:475`) — APPROXIMATION,
documented deviation (not a closure state).** Unlike mirror-clamp (feature
bit, advertised FALSE, rejected) and LOD bias (limit, now advertised 0),
CLAMP_TO_BORDER is core Vulkan with no feature bit and no limit: there is
no advertisement lever, and a conforming guest may always create such a
sampler. WebGPU has no border addressing or border colour (decoder:
`web/vk-protocol.mjs:89-90`; descriptor: `web/vkwebgpu.mjs:214-215`), and a
true implementation would need shader-level border emulation in the
SPIR-V-to-WGSL tier, which does not exist. Rejection was considered and
rejected itself: failing core sampler creation makes DXVK throw from
vkCreateSampler wherever D3D9/D3D11 border addressing is used
(shadow-map PCF, edge fade), converting a latent visual approximation into
a hard failure of conforming guests. The approximation therefore stays,
described in the row exactly as the code behaves, logged per sampler as
`sampler-border-colour` with the colour value, and pinned by
`vk-sampler-rejection.test.mjs`. The demo-log sweep found no workload
creating a border sampler today, so the deviation is latent. It remains
tracked here as a deviation, explicitly NOT counted as IMPLEMENTED,
REJECTED-LOUDLY, or NOT-A-GAP; closing it requires either the
shader-emulation feature (IMPLEMENTED) or a project decision to fail a
core feature loudly (REJECTED-LOUDLY).
