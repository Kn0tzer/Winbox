# Winbox status — read this first

_This file says where the truth lives. It deliberately carries no
build hashes, register counts, or demo verdicts: anything that can
change names its source instead, and the source wins over any
summary, including this one. The full documentation map is
`docs/INDEX.md`. Dated state snapshots that used to live here are
preserved unedited in
`docs/reports/status-snapshots-20261030-20261105.md`._

## What this is

Winbox runs Windows apps and games in a browser: 32-bit and 64-bit
CPU emulation compiled to WebAssembly, a Wine userspace, and
OpenGL / Vulkan / DirectX 9–12 bridged to WebGPU. Live site:
https://kn0tzer.work.gd/winbox

## Where the truth lives

- **What is live:** the site stamps itself. `runtime/BUILD_INFO.json`
  served from the live site names the exact commit and program hash
  in production; read it rather than trusting any document. Each
  deploy is recorded in a dated `docs/reports/deploy-*.md` record and
  keeps exactly one rollback copy beside the live tree; the newest
  deploy record by date is the current one.
- **What is broken or missing:** one queue —
  `docs/defect-register.md`. Its open section is the development
  queue; a closure names its fixing commit and its proof. The
  standing compatibility registers in `docs/known-gaps/` hold the
  detailed per-area record, guarded by tests; their headers carry
  the current counts. One register file,
  `runtime-artifact-manifest.md`, is generated by
  `tools/rootfs64/gen_runtime_manifest.py` — never hand-edit it.
- **Demo support:** `docs/game-compatibility.md` — verified evidence
  only. Its header names the sweep or measurement each row rests on;
  check the evidence date before quoting a verdict.
- **How the runtime fits together:** `docs/architecture.md`.
- **Build and probe coordination:** `BUILD_PROTOCOL.md` at the repo
  root. Day-to-day workflow (worktrees, builds, probes, waiting):
  `docs/workflow.md`.
- **Campaign history:** `docs/reports/` holds the dated records;
  `docs/reports/README.md` is their index. A record describes the
  build it names, not the current checkout.
- **Standing standards:** failure logging and recovery patterns:
  `docs/failure-logging-and-recovery.md`.

## Standing state that is not a measurement

- The networking campaign is parked by the user's order. Program
  internet access as it exists today is described in
  `docs/architecture.md`.
- Development work is drawn from the defect register's open section.
  A lane that finds a new defect files it there before its report
  counts as filed; closing an entry requires the fixing commit and
  its proof.
